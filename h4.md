# Johnny Tables - Web Security Report

## Read and Summarize

### OWASP Top 10 - 2021

**A01:2021 - Broken Access Control**
- Occurs when users can access data or perform actions they shouldn’t.
- Examples include viewing other users' data, modifying permissions, or bypassing authentication.
- **Question:** How do large systems enforce access control properly?
- **Comment:** This is one of the most common security vulnerabilities and can have serious consequences.
- **Thought:** Access control mechanisms should be regularly tested to prevent privilege escalation attacks.

**A05:2021 - Security Misconfiguration**
- Happens when security settings are left at defaults or are poorly configured.
- Common causes: unnecessary features enabled, default credentials, exposed error messages.
- **Question:** How often do companies forget to remove default passwords, and what are the best strategies to prevent this?
- **Comment:** Regular security audits can help detect misconfigurations early.
- **Thought:** Automated tools should be used to scan and fix misconfigurations before deployment.

**A06:2021 - Vulnerable and Outdated Components**
- Using outdated libraries, plugins, or software with known vulnerabilities.
- Attackers exploit these to gain access or execute malicious code.
- **Question:** Why do companies delay software updates despite known risks?
- **Comment:** Keeping everything updated is the easiest way to avoid this.
- **Thought:** Dependency management tools should be integrated into the software development process to ensure all components are up to date.

**A03:2021 - Injection**
- Occurs when an attacker inserts malicious code (SQL, script, OS commands) into an input field.
- Can allow data theft, database manipulation, or system takeover.
- **Question:** How do modern web frameworks prevent SQL injection by default?
- **Comment:** User input must always be sanitized and validated.
- **Thought:** Developers should use parameterized queries and prepared statements to mitigate injection risks.

### XKCD 327 - Exploits of a Mom
- Highlights real-world consequences of SQL injection.
- Demonstrates why user input should never be trusted.
- **Question:** What are the most effective ways to train developers to prevent injection vulnerabilities?
- **Comment:** This comic is a great way to introduce SQL injection risks to beginners.

### e) PortSwigger Lab: SQL Injection
- Found and exploited a SQL injection vulnerability in the WHERE clause.
- Steps:
  1. Identified a vulnerable input field.
  2. Injected "' OR 1=1 --" to bypass authentication.
  3. Retrieved hidden data by modifying SQL queries.
- **Analysis:**
  - The exploit works because user input is directly included in SQL queries.
  - Proper input validation and prepared statements can prevent this.
- **Thought:** Learning SQL injection techniques helps understand how to protect applications from such attacks.
